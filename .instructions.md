# Town of Wiley AI Workspace Instructions

Use these instructions when generating, editing, or reviewing code in this workspace.

## Project Context

- This repository is an Angular 21 application with standalone components, signals-first patterns, native control flow, strict accessibility expectations, Playwright e2e coverage, and AWS-backed infrastructure.
- Treat `.vscode/angular-best-practices.md` as the source of truth for Angular, TypeScript, accessibility, component, template, service, and responsive-design guidance.
- Treat `.vscode/llms.txt` as the quick Angular context bundle for this workspace.
- Treat `.github/instructions/ai-application-development.instructions.md` as the source of truth for AI feature integration, provider security boundaries, tool calling, and graceful degradation.
- Treat `.cursor/rules/*.mdc` (core-workflow.mdc, angular-standards.mdc, ai-integration.mdc) as the consolidated, persistent Cursor AI rules incorporating all workspace standards, skills, and best practices. These take precedence for AI agent behavior.

## Angular Requirements

- Prefer standalone Angular APIs, signals, `input()`, `output()`, `computed()`, and `inject()`.
- Use `ChangeDetectionStrategy.OnPush` for components.
- Prefer native control flow blocks (`@if`, `@for`, `@switch`) over structural directives.
- Prefer reactive forms over template-driven forms.
- Avoid `ngClass` and `ngStyle`; prefer class and style bindings.
- Keep templates semantic and accessible, and meet WCAG AA requirements.

## Codebase RAG

- For cross-cutting “where is X?” questions, use local RAG per [`docs/codebase-rag.md`](docs/codebase-rag.md): MCP **`townofwiley-rag`** / `search_codebase`, or `npm run rag:query -- "…"` after `rag:setup` + `rag:index`.
- The index covers source, docs, agent instructions, `rag/tow_rag/` (self-description), and `.github/skills/`.
- Follow [`.cursor/rules/codebase-rag.mdc`](.cursor/rules/codebase-rag.mdc); read cited line ranges before editing. Re-index (prefer incremental) after large changes.

## Cursor Agent Auto-Approval Policy

Follow the **Cursor Agent Auto-Approval & Execution Policy** defined in [`.cursor/rules/core-workflow.mdc`](.cursor/rules/core-workflow.mdc) (the alwaysApply rule).

- You may auto-approve routine edits and safe dev commands that obey the project standards.
- Ask for confirmation on anything destructive, mutating, secret-related, or production-impacting.
- A project hook (`.cursor/hooks/pre_tool_use.py`) further enforces safe terminal auto-run behavior.

## AI Tooling Expectations

- For Angular-specific tasks, ALWAYS start by consulting Angular CLI MCP (via CallMcpTool or equivalent), then `.cursor/rules/angular-standards.mdc` and core-workflow.mdc before any code changes.
- For CI/CD, secrets sync, PR validation, and deploy commands, follow [`docs/pipeline-workflow.md`](docs/pipeline-workflow.md) and [`.github/copilot-instructions.md`](.github/copilot-instructions.md).
- Use repo-local guidance before inventing patterns: `.cursor/rules/*.mdc`, `.instructions.md`, `.github/skills/TownOfWiley-Dev/SKILL.md`, `.github/instructions/*.instructions.md`, and `.github/copilot-instructions.md`.
- For AI-powered feature work, follow `.github/instructions/ai-application-development.instructions.md`, `.cursor/rules/ai-integration.mdc`, and route larger tasks through `.github/agents/ai-feature.agent.md` when appropriate.
- For Playwright work, follow `.github/instructions/playwright-testing.instructions.md`, use **`playwright-test`** (`test_run` / pre-push) vs **`microsoft/playwright-mcp`** (explore only) from [`.cursor/mcp.json`](.cursor/mcp.json) and [`.vscode/mcp.json`](.vscode/mcp.json), VS Code tasks **`e2e: smoke (CI parity)`** / **`e2e: pre-push`** in [`.vscode/tasks.json`](.vscode/tasks.json), and run **`npm run e2e:init-agents`** after Playwright version bumps.

## Evaluation And Validation

- Prefer the existing workspace scripts for build, lint, unit tests, Vitest, and Playwright validation.
- Web Codegen Scorer is available for Angular-focused AI evaluation through `archive/hello-world/config.mjs` (see `archive/README.md`).
- Keep changes minimal and aligned with existing project structure and styling.
