# CMS model → GraphQL → site routes

Single source of truth for which **Amplify Studio / AppSync** models feed which **townofwiley.gov** surfaces. Use this when changing [`amplify/backend/api/townofwiley/schema.graphql`](../amplify/backend/api/townofwiley/schema.graphql) or [`src/app/site-cms-content.ts`](../src/app/site-cms-content.ts) `PUBLIC_CMS_QUERY`.

**Staff workflow:** edit records on **`/admin`** → task hub → **Edit content** (in-app forms → AppSync GraphQL with Cognito). IT may use the **AppSync Queries console** (link under **Advanced (IT)** → **Open content editor**). Amplify Studio / Data Manager is **deprecated** (June 2026). The public site **never** writes to the CMS; it reads via `PUBLIC_CMS_QUERY` and an API key in [`public/runtime-config.js`](../public/runtime-config.js) (generated by [`scripts/generate-runtime-config.mjs`](../scripts/generate-runtime-config.mjs)).

## Stable `OfficialContact` record IDs

The app resolves specific contacts by **Dynamo `id`**, not by display text. These IDs **must** exist on `OfficialContact` rows (or the app uses bundled fallbacks):

| `id` (exact)          | Used by                                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| `town-information`    | `/contact` Town Administration intro; `app.ts` footer; `resident-services`, `accessibility-support` |
| `city-clerk`          | `/contact` clerk mailto on administration roster lines; `permits`, `resident-services`, `accessibility-support` |
| `town-superintendent` | `/contact` superintendent mailto on administration roster lines                                 |

Constants: `OFFICIAL_CONTACT_ID_TOWN_INFORMATION`, `OFFICIAL_CONTACT_ID_CITY_CLERK`, `OFFICIAL_CONTACT_ID_TOWN_SUPERINTENDENT` exported from [`src/app/site-cms-content.ts`](../src/app/site-cms-content.ts).

## `/contact` page layout (2026)

| Section | Source |
| ------- | ------ |
| **Town Hall** card (address, hours, phone) | Mostly `APP_COPY` + fixed address — not CMS-driven |
| **Town Administration** card | `OfficialContact` `town-information` summary + `LeadershipRosterEntry` `town-administration` lines (mailto enriched from `city-clerk` / `town-superintendent`) |
| **Elected Officials** (`#leadership`) | `LeadershipRosterEntry` `mayor-council` lines (role + name only) |

`/records` redirects to `/contact`. There is no records-assistance callout on `/contact`.

## Stable `LeadershipRosterEntry.groupId` values

Bullets on `/contact` merge CMS lines into the bundled `APP_COPY` groups by **`groupId`** (not by title text):

| `groupId` (exact)     | Section on `/contact`                                                                 |
| --------------------- | ------------------------------------------------------------------------------------- |
| `mayor-council`       | **Elected Officials** at `#leadership` / Funcionarios electos                       |
| `town-administration` | Roster lines inside **Town Administration** card (not the elected section)            |

Constants: [`src/app/leadership-roster-group-ids.ts`](../src/app/leadership-roster-group-ids.ts).

## Field names (schema-accurate)

Use these names in Studio so they match the app and [`PUBLIC_CMS_QUERY`](../src/app/site-cms-content.ts):

- **AlertBanner:** `enabled`, `label`, `title`, `detail`, `linkLabel`, `linkHref` (URL — not `linkUrl`).
- **OfficialContact:** `label`, `value`, `detail`, `href`, `linkLabel`, `displayOrder` — the **`id`** is the stable key above.
- **LeadershipRosterEntry:** `groupId` (`mayor-council` or `town-administration`), `displayOrder`, `lineEn`, `lineEs`, `active` — one GraphQL row per bullet line; replaces bundled lines for that `groupId` when any active CMS rows exist.
- **Announcement:** includes `announcementKind`, `attachmentKey` for `/news` newsletter PDF behavior (see clerk guide).

## Staff-only vs public models

- **Public models** (rows with “In `PUBLIC_CMS_QUERY`? = Yes”) are readable with the website API key and appear on townofwiley.gov within seconds after save (live AppSync on each page load).
- **EmailAlias** is **authenticated staff only** — clerks edit it on **`/admin`** (task **Manage email forwarding**). It must never be added to `PUBLIC_CMS_QUERY`. See [CLERK-CMS-GUIDE.md](./CLERK-CMS-GUIDE.md#managing-email-aliases--proxy-settings).

**Gen 1 production API:** AppSync `j7b2x3sh7rcezekekkxxiak7hi` — public read + staff writes via `/admin`. Gen 2 app was decommissioned; see [`gen2-decommissioned.md`](./gen2-decommissioned.md).

## CI drift check

`npm run verify:public-cms-query` (see [`scripts/verify-public-cms-query.mjs`](../scripts/verify-public-cms-query.mjs)) ensures `PUBLIC_CMS_QUERY` only lists models that allow anonymous read, and that `EmailAlias` is not queried from the browser. IT runs this in CI; clerks use **Force Refresh Live CMS Content** on `/admin` when the site looks stale (see [Troubleshooting Content Not Updating](./CLERK-CMS-GUIDE.md#troubleshooting-content-not-updating) in the clerk guide).
